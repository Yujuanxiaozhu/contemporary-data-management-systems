==================================================
二、统计总体原则
==================================================

统计数据来源：

responses

题目结构来源：

survey_versions

不要依赖当前 surveys.questions 去解释历史 response。

不要建立写入时维护的永久统计计数器。

不要在 response 提交时执行：

count += 1

本阶段统计应根据已经保存的 response 动态计算。

原因：

系统支持历史 schema_version，同一个 question_id 在不同版本中可能：

- options 不同
- validation 不同
- 类型不同
- 不存在

强行跨不兼容版本合并会产生错误统计语义。

因此统计必须按 schema_version 明确分组。

==================================================
三、整份问卷统计 API
==================================================

实现或完善：

GET /api/surveys/{survey_id}/stats

必须登录。

必须是 survey owner。

非 owner 保持现有权限策略，例如返回 404。

非法 survey ObjectId 不得产生 500。

建议返回结构：

{
  "survey_id": "...",
  "total_responses": 30,
  "versions": [
    {
      "schema_version": 3,
      "response_count": 20,
      "questions": [...]
    },
    {
      "schema_version": 4,
      "response_count": 10,
      "questions": [...]
    }
  ]
}

要求：

total_responses：

统计该 survey 的全部合法已保存 response。

versions：

按 survey_schema_version 分组。

每一个 version 必须使用对应：

survey_versions

中的 immutable snapshot 解释题目。

不要使用当前 survey 最新结构解释旧答卷。

没有 response 的当前 published version，如果合理，可以返回零统计，但行为必须文档化并保持一致。

==================================================
四、单题统计 API
==================================================

实现或完善：

GET /api/surveys/{survey_id}/questions/{question_id}/stats

必须 owner 才能访问。

返回所有存在该 question_id 且有统计意义的历史 schema version。

例如：

{
  "survey_id": "...",
  "question_id": "q1",
  "versions": [
    {
      "schema_version": 3,
      "question": {...},
      "response_count": 12,
      "statistics": {...}
    },
    {
      "schema_version": 4,
      "question": {...},
      "response_count": 6,
      "statistics": {...}
    }
  ]
}

如果同一个 question_id 历史上改变了 type：

不要合并统计。

分别返回各 schema_version 的结果。

如果 question 在某些版本不存在：

不要伪造零值题目。

==================================================
五、single_choice 统计
==================================================

对单选题至少统计：

- answered_count
- 每个 option 的 count

结构可类似：

{
  "type": "single_choice",
  "answered_count": 20,
  "options": [
    {
      "option_id": "a",
      "label": "苹果",
      "count": 12
    },
    {
      "option_id": "b",
      "label": "香蕉",
      "count": 8
    }
  ]
}

必须使用该 snapshot 中的 option 定义及 label。

不得使用当前最新 survey option label 覆盖历史版本。

如果 response 中出现违反历史 snapshot 的数据：

正常情况下不应发生。

统计 service 不要静默把未知 option 计入一个不存在的合法选项。

采取明确策略并测试，例如：
- 忽略并记录异常
或
- 抛出数据一致性错误

优先选择不会产生错误正常统计结果的安全策略。

==================================================
六、multiple_choice 统计
==================================================

至少统计：

- answered_count
- total_selections
- 每个 option 被选择次数

例如一个 respondent：

["a", "b", "c"]

则：

answered_count +1
total_selections +3

每个对应 option count +1。

不要把多选题：

选项被选择次数

错误解释为：

有多少份 response。

==================================================
七、text 统计
==================================================

至少返回：

- answered_count
- 所有有效文本内容 values

例如：

{
  "type": "text",
  "answered_count": 5,
  "values": [
    "文本1",
    "文本2"
  ]
}

optional 且没有答案：

不计入 answered_count。

skipped question：

不计入。

不要做 NLP、关键词提取或词云。

==================================================
八、number 统计
==================================================

至少返回：

- answered_count
- values
- average

可以额外返回：

- min
- max

但不是强制。

average：

只根据实际存在的合法数字答案计算。

没有数字回答时：

不要出现除零问题。

明确设计：

average = null

或等价安全表达。

必须处理：

- integer
- float
- bool 不得被当作 number
- 非有限数不应存在

如果数据库出现异常历史数据，采取明确安全策略。

==================================================
九、跳转与统计
==================================================

统计以实际 response.answers 为准。

被跳过的问题：

没有 answer

因此：

- 不计入 answered_count
- 不计入选项次数
- 不进入 text values
- 不进入 number average

不要根据所有 response 数量推断每题回答人数。

例如：

100 人提交问卷

只有 30 人经过 q5

则：

q5 answered_count 最大应是 30

而不是 100。

==================================================
十、历史版本统计
==================================================

这是本轮重点。

例如：

version 2：

q1 single_choice
A
B

version 3：

q1 single_choice
A
B
C

version 4：

q1 number

必须分别统计：

version 2 q1
version 3 q1
version 4 q1

禁止生成一个混合 q1 统计。

整份问卷统计必须包含所有有 response 的历史版本，而不是只统计当前版本。

这样旧填写数据不会因为问卷升级而消失。
